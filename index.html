二、嵌入式系统的定义

标准定义：嵌入式系统是以应用为中心、以计算机技术为基础、软硬件可裁剪，适用于应用系统对功能、可靠性、成本、功耗等有严格要求的专用计算机系统。

关键词拆解

  • 以应用为中心：针对具体应用场景定制，不是万能设备。
  • 以计算机技术为基础：本质仍是计算机系统。
  • 软硬件可裁剪：按需选择硬件资源和软件模块。
  • 专用计算机系统：区别于通用 PC。
补充：嵌入式系统与通用计算机对比见下表。
维度嵌入式系统通用计算机
定位专用功能通用任务
软硬件可裁剪、资源受限资源丰富、可扩展
功耗/体积通常低功耗、小体积功耗和体积较大
操作系统裁剪定制（Linux、RTOS 等）Windows、macOS 等

三、嵌入式系统的组成

课上强调为三大部分：

  • 硬件层：核心是处理器（芯片），如 ARM、8051 内核的 MCU；外围硬件包括内存、硬盘/U 盘、VGA/HDMI、投影等。
  • 嵌入式操作系统：运行在硬件之上，与 PC 通用 OS 不同，通常更精简、可裁剪。
  • 嵌入式软件：面向具体应用的用户程序，最终运行在目标硬件上。
补充：教材中也常见“硬件层 / 中间层（BSP）/ 操作系统层 / 应用层”四层说法。三部分是大分类，中间层属于对硬件的抽象与适配，不要混淆。

四、ARM 与嵌入式微处理器

4.1 两大主流架构

架构典型设备
x86PC、笔记本
ARM手机、平板、手持设备

4.2 ARM 的三种含义

  1. 公司名称：ARM 公司。
  2. 微处理器的统称/架构：基于 ARM 内核的处理器。
  3. 技术名称：ARM 架构技术。

4.3 商业模式与芯片产业链

  • ARM 公司不直接造芯片，主要研发并授权 IP 核（知识产权核）。
  • IP 核是“芯片的主要架构与核心设计”，不是网络 IP 地址。
  • 产业链：IP 授权 → 芯片设计（合作伙伴）→ 晶圆代工（如台积电）→ 渠道销售 → 终端用户。
  • 芯片/电路模块使用防静电袋包装：人体静电瞬间放电可达上万伏，可能击穿芯片。
补充：IP 核常分为软核、固核、硬核。软核灵活但需综合实现；硬核性能确定、不可修改；固核介于二者之间。

4.4 RISC 与 CISC

  • RISC：精简指令集计算机（Reduced Instruction Set Computer）。
  • CISC：复杂指令集计算机（Complex Instruction Set Computer）。
  • ARM 采用 RISC；传统 PC 的 x86 更偏向 CISC。

五、ARM 系列与架构对比

5.1 ARM 系列

系列架构特点
ARM7冯·诺依曼架构成熟、批量大、3 级流水线、RISC、低功耗
ARM9 / ARM10 / ARM11哈佛架构程序与数据总线分离，流水线级数更高，效率更高
Cortex 系列面向不同应用STM32 基于 Cortex-M 内核

5.2 冯·诺依曼 vs 哈佛架构

冯·诺依曼架构：

  • 组成：运算器、控制器、存储器、输入设备、输出设备。
  • CPU = 运算器 + 控制器。
  • 特点：程序指令与数据共用同一总线，可能出现“拥堵”。

哈佛架构：

  • 程序存储器与数据存储器的总线相互独立。
  • 指令与数据可并行访问，处理效率更高。
  • 类比：教室两个门，一个进、一个出，比单门同时进出更快。

六、嵌入式系统开发流程

开发包括三部分：总体开发、硬件开发、软件开发。

  1. 系统定义与需求分析（可行性分析）：岗位对应产品经理，立项前与甲方对接、调研需求，明确功能、性能、规格，避免后期反复改动。
  2. 硬件开发 / 软件开发并行：明确各自功能与约束，形成方案与合同，再执行。
  3. 验收与闭环：软硬件联调适配；不满足需求则返回修改，形成大循环。
重点：流程图很关键。顺序步骤用流程框，条件分支用判断框，对应代码中的 if、if-else、switch-case。

七、自顶向下 vs 自底向上设计

方法思路类比优缺点
自顶向下（Top-Down）把大系统按模块拆分，先总体后细化装修教室：先分讲台、桌椅、照明、投影模块单模块修改不影响其他模块，易维护
自底向上（Bottom-Up）从底层一步步向上搭建盖房子：先打地基再砌墙底层出问题需要层层拆除，修改成本高

结论：实际设计中二者交替结合，但以自顶向下为主体。

八、交叉编译

  • 普通编译：在电脑（x86）上写代码、编译，并下载/烧录到目标板。
  • 交叉编译：在宿主机（如 x86 的 PC）上，借助交叉编译器，生成能在目标机（如 ARM）上运行的目标代码。
  • 原因：x86 平台编译出的程序不能直接运行在 ARM 架构上。
补充：常见交叉编译链如 arm-linux-gnueabihf-gcc，用于生成 ARM Linux 可执行文件。

十一、Linux 指令基础

  • 指令格式：命令 + 空格 + 操作对象，两者之间必须有空格。
  • 区分大小写：ls 有效，LS 无效。
  • Shell：既是命令解释器，也是一门脚本编程语言。
  • 常用分类：文件管理、用户管理、打包压缩、磁盘管理、网络管理、进程管理等。
指令作用
ls列出当前目录内容
cd /home切换到 /home 目录
clear清屏
sudo useradd 用户名以管理员权限添加用户

useradd 实操要点

  • 添加用户需要 root/管理员权限，普通用户需用 sudo。
  • 输入密码时不回显（安全机制），并非没输入进去。
  • 创建成功后会在 /home 下生成对应用户目录，并分配 UID（用户 ID）、GID（组 ID）。
  • 密码过短（如 123456）系统会提示，但学习阶段仍可继续。
补充——常用指令速查：pwd 显示当前路径；mkdir 新建目录；rm 删除文件；cp 复制；mv 移动/重命名；passwd 修改用户密码。

十二、易错点复盘

  • 命令与对象之间忘加空格，系统无法识别。
  • Linux 大小写敏感，LS ≠ ls。
  • 普通用户直接 useradd 会因权限不足失败，需加 sudo。
  • 输入密码不显示星号是正常现象，不代表没输入。
  • 虚拟机资源不要分配过高，避免拖慢宿主机。
  • 桥接模式下网络图标为问号表示未联网，联网后会变化为已连接图标。
