二、嵌入式系统的定义 ★

标准定义：嵌入式系统是以应用为中心、以计算机技术为基础、软硬件可裁剪，适用于应用系统对功能、可靠性、成本、功耗等有严格要求的专用计算机系统。

关键词拆解

  • 以应用为中心：按具体任务定制（如空调控制器只负责温控）。
  • 以计算机技术为基础：本质仍是计算机系统。
  • 软硬件可裁剪：硬件按需减少外设，软件按需裁剪模块。
  • 专用计算机系统：与通用 PC 相对，通常只完成特定功能。

主要特点（扩充）

特点说明
专用性面向特定应用定制
可裁剪性软硬件均可按需增删
实时性多数系统要在规定时间内响应（如安全气囊毫秒级触发）
资源受限内存、Flash、功耗、体积、成本受约束
高可靠性长期运行、环境恶劣仍需稳定
软硬件紧耦合需软硬件协同设计

vs 通用计算机（扩充）

维度嵌入式系统通用计算机
定位专用功能通用任务
软硬件可裁剪、资源受限资源丰富、可扩展
功耗/体积低功耗、小体积功耗和体积较大
操作系统裁剪定制（Linux、RTOS，甚至裸机）Windows、macOS 等
开发调试交叉开发、烧录调试本机开发调试
升级维护较难，需专门工具方便
常见考法：填空“以___为中心、以___为基础、软硬件___”，或简答“嵌入式系统的特点”。

三、嵌入式系统的组成 ★

三大部分（课堂强调）

  • 硬件层：核心是处理器（芯片），如 ARM、8051 内核 MCU；外围包括内存、USB、VGA/HDMI、投影、传感器等。
  • 嵌入式操作系统：精简、可裁剪，如嵌入式 Linux、FreeRTOS。
  • 嵌入式软件：面向具体应用的程序，下载/烧录到目标硬件运行。

更完整的四层结构（扩充）

层次内容作用
应用层应用程序实现具体业务功能
操作系统层内核、文件系统、网络协议栈管理资源、提供系统服务
中间层BSP / HAL / 驱动屏蔽硬件差异，统一接口
硬件层CPU、存储、I/O、外设、总线系统物理基础
理解要点：课堂“三部分”是宏观分类；教材的“中间层”属于软硬件之间的适配层，不必对立记忆。

硬件核心部件（扩充）

  • CPU/处理器：MCU、MPU、DSP、SoC（见第十四章）。
  • 存储器：RAM（运行程序）、ROM/Flash（固件）。
  • I/O 与总线：GPIO、UART、SPI、I2C、CAN、USB、以太网。
  • 电源与时钟：供电电路、晶振。

四、ARM 与嵌入式微处理器 ★

4.1 两大主流架构

架构典型设备指令集特点
x86PC、笔记本、服务器CISC 复杂指令集性能强、功耗高、生态成熟
ARM手机、平板、嵌入式设备RISC 精简指令集低功耗、低成本、应用广
扩充：手机对功耗、散热极敏感，ARM 以低功耗见长；近年 ARM 也开始进入笔记本/服务器（如 Apple M 系列）。

4.2 ARM 的三种含义

  1. 公司名称：ARM 公司（Advanced RISC Machines，1990 年成立）。
  2. 微处理器的统称：基于 ARM 内核的处理器。
  3. 技术名称：ARM 架构本身（指令集与内核规范）。

4.3 商业模式：卖 IP 核

  • ARM 不直接造芯片，研发并授权 IP 核（知识产权核）。
  • IP 核是“芯片的架构与核心设计”，不是网络 IP 地址。
  • 收费方式：授权许可费 + 版税。

4.4 IP 核三种形态（扩充）

类型提供形式灵活性
软核 Soft CoreHDL 代码（Verilog/VHDL）高，可综合重配置
固核 Firm Core综合网表/布局约束中，跨工艺需重优化
硬核 Hard Core已定版图、工艺固定低，性能确定不可改

4.5 芯片产业链（扩充）

IP 授权（ARM） ↓ 芯片设计（高通/三星/联发科等） ↓ 晶圆代工（台积电、中芯国际等） ↓ 封装测试 → 渠道零售 → 终端用户

4.6 8051 背景（扩充）

  • 主流单片机（STC、AT89 等）内核是 8051；51/52 区别主要在片内 RAM 大小。
  • 4 个 I/O 口：P0 ~ P3，每口 8 位，用于 LED、按键、中断、串口实验。
  • 8051 是 8 位处理器；STM32 是 32 位处理器（寄存器更多、更复杂）。
  • 32 位处理器直接查手册开发效率低，通常用库函数/驱动库开发（标准库、HAL 库）。
防静电：人体静电瞬时放电可达上万伏，可能击穿芯片；芯片使用防静电袋包装，操作注意防静电手环、接地。

五、ARM 系列与架构对比 ★

5.1 ARM 系列演进

系列架构特点
ARM7冯·诺依曼架构成熟大批量、3 级流水线、RISC、低功耗（约 130 MIPS）
ARM9 / ARM10 / ARM11哈佛架构总线路分离，流水线级数更高，效率更高
Cortex 系列按应用细分 A/R/MSTM32 采用 Cortex-M

5.2 Cortex 三大系列（扩充）

系列目标典型应用
Cortex-A高性能应用处理器手机 SoC、平板、树莓派
Cortex-R硬实时、高可靠汽车刹车/气囊、硬盘控制器
Cortex-M低功耗单片机STM32、GD32 等 MCU、物联网
扩充——Thumb 指令集：ARM 的 16 位 Thumb 指令、16/32 位混合的 Thumb-2 指令，在代码密度与性能间取得平衡，Cortex-M 广泛使用。

5.3 冯·诺依曼架构

  • 组成：运算器、控制器、存储器、输入、输出；CPU = 运算器 + 控制器。
  • 特点：程序与数据共用一条总线，可能拥堵；结构简单、成本低。

5.4 哈佛架构

  • 特点：程序与数据总线分离，可并行访问，效率更高。
  • 类比：教室两个门，一个进一个出，比单门快。

5.5 流水线（扩充）

指令执行分“取指 → 译码 → 执行 → 写回”等阶段，多级流水线让多条指令重叠执行。ARM7 为 3 级，ARM9 为 5 级，级别越高吞吐越快。

5.6 RISC vs CISC（扩充）

维度RISC（ARM）CISC（x86）
指令少而精、定长多而复杂、变长
执行多单周期，适合流水线复杂指令微码实现
功耗低高
依赖靠编译器优化硬件承担更多

6.1 三大开发

嵌入式系统开发包括：总体开发、硬件开发、软件开发。

6.2 详细流程（扩充）

系统定义与需求分析（产品经理） ↓ 需求规格说明书 SRS ↓ ┌── 硬件开发 ──┐ ┌── 软件开发 ──┐ │ 原理图设计 │ │ 概要/详细设计 │ │ PCB 设计/制板 │ │ 编码 │ │ 硬件调试 │ │ 编译/单元测试 │ └─────┬────────┘ └─────┬────────┘ └── 软硬件联调（验证测试）──┘ ↓ 验收；不合格返回修改（闭环大循环） ↓ 交付与维护
  • 产品经理：立项前与甲方对接、调研需求，明确功能/性能/规格，避免反复改动。
  • 验收：软硬件适配跑通才算合格；不符合需求返回修改，形成大循环。
  • 流程图是重点：顺序步骤用流程框（矩形），判断条件用判断框（菱形），对应 if、if-else、switch-case。

模型特点适用

迭代/增量分块开发逐步完善需求易变的中大型项目

七、自顶向下 vs 自底向上 ★

方法思路类比优缺点
自顶向下 Top-Down按模块拆分，先总体后细化装修教室：讲台/课桌/照明/投影单模块修改影响小、易维护
自底向上 Bottom-Up从底层逐层搭建盖房子：先打地基再砌墙底层出问题返工成本高

课堂案例复盘

  • 桌椅摆放：不合理只改桌椅模块，不动讲台黑板。
  • 照明：灯横向摆，灯在身后影子遮作业本；纵向摆阴影更小。
  • 盖房子：地基不牢（2 米而非 7 米），上层全出问题，返工层层拆。
扩充——模块化原则：高内聚（模块内功能紧密相关）、低耦合（模块间依赖少），便于开发、测试、替换、复用。

结论：实际二者交替结合，整体以自顶向下为主体。

八、交叉编译 ★

8.1 为什么要交叉编译

  • 目标设备（ARM）资源有限，不在目标板上开发。
  • x86 上编译的程序不能直接在 ARM 上运行（指令集、ABI 不同）。
  • 解决：在宿主机 Host 上用交叉编译器生成在目标机 Target（ARM）上运行的代码。
编译方式宿主机目标机工具
本机编译x86 PCx86 PCgcc（本地）
交叉编译x86 PC（开发机）ARM 等嵌入式目标交叉编译器

8.2 交叉工具链构成（扩充）

组件作用
binutils汇编器 as、链接器 ld、objcopy/objdump
GCC 交叉编译器生成目标架构机器码，如 arm-linux-gnueabihf-gcc
C 运行库glibc / musl / uClibc
GDB 调试器远程/模拟调试

工具链前缀解读：arm-linux-gnueabihf-gcc：arm=目标架构，linux=目标系统，gnueabihf=GNU 工具链 + 硬件浮点，gcc=C 编译器。

8.3 典型流程

PC 编写源码 → 交叉编译 → 生成 ARM 可执行文件 （.elf / .bin / .hex）→ 烧录到目标板 → 运行调试

8.4 软件下载方式（扩充）

方式说明
调试器烧录J-Link / ST-Link，通过 JTAG/SWD
串口 ISPUART 引导程序下载（STC、Bootloader）
网络 TFTP/NFS网口取文件，方便反复调试
存储介质SD 卡、U 盘拷贝
扩充——构建系统：用 Makefile 或 CMake 组织编译，一条 make 按依赖关系编译整个工程，避免手动敲多条 gcc 命令。

二、课前复习（第 2 课回顾）

  • cp 复制文件 vs 文件夹：复制文件 cp 文件 目标 不加 -r；复制文件夹 cp -r 目录 目标 必须加 -r（递归），否则报错。
  • 绝对路径与相对路径：在同一上级目录内操作，目标只是二级目录不同；跨到并列目录是“绝对性变化”，要写完整绝对路径。
  • 类比：从主楼到旁边楼 vs 在新楼内部换房间，路径差别完全不同。
课堂提问回顾：cp 复制文件与复制文件夹有没有区别？→ 有。文件夹必须加 -r，把文件夹及内部所有文件全部递归复制；即使是空文件夹也必须要加。

三、mv：移动文件或目录 ★

3.1 含义

mv = move（移动），相当于把东西从一个地方搬到另一个地方。类比：教室从西区 0101 整体搬到 ES0304，原教室不再有人。

3.2 格式与示例

mv 源 目标
示例作用
mv file1 /home/DIR2/把 file1 移动到 /home/DIR2
mv /home/DIR1/dir1 /home/DIR2/把目录 dir1 移动到 /home/DIR2
mv old.c new.c改名（移动 + 重命名）

3.3 课堂验证要点

  1. 移动目录不需要加 -r：mv 与 cp 的最大区别，直接 mv 目录 目标。
  2. 保留时间戳：mv 后目标文件时间戳仍是原文件创建时间；cp 复制后是复制时刻。用 ll 验证。
  3. 源消失：移动后原路径下文件/目录不存在，用 ls 双向验证。
  4. 查看其他目录不用进入：直接 ls /home/DIR2。

类比Ctrl+C / Ctrl+V剪切 + 粘贴

五、文件类型：ll 的“第一列” ★

5.1 为什么要学

ll（= ls -l）第一列第一个字符表示文件类型，后 9 位表示权限。看懂第一列是读懂 ll 的基础。

5.2 常见文件类型

首字符类型英文说明
-普通文件regular file文本、二进制、脚本、C 源码等
d目录文件directory即文件夹

p管道文件pipe进程间通信
联系“一切皆文件”：普通文件、文件夹、设备、管道、链接都以文件形式存在，所以 Linux 说“一切皆文件”。

5.3 示例解读

-rw-r--r-- 1 asus asus 123 9月20日 11:39 hello.c drwxr-xr-x 2 asus asus 4096 9月20日 11:29 dir1 lrwxrwxrwx 1 asus asus 10 9月20日 11:49 shello.c -> hello.c

六、权限 rwx 详解 ★

6.1 三个符号

符号英文含义
rread可读：能查看/浏览内容
wwrite可写：能编辑并保存
xexecute可执行：能作为程序运行
  • 读 ≠ 写：能看不代表能改，写了才能修改内容。
  • 对目录：r=能列出内容，w=能增删文件，x=能进入目录。

6.2 三组对象 u / g / o

组英文含义
uuser文件所有者（owner）
ggroup所属组的用户
oothers其他用户

权限共 9 位：u(rwx) + g(rwx) + o(rwx)，顺序固定不可调换。

6.3 数字表示法 ★

  • 二进制转十进制：rwx 每位对应 4、2、1（2²、2¹、2⁰）。
  • 有权限写 1、无权限写 0，然后求和。
权限二进制十进制含义
rwx1117读+写+执行
rw-1106读+写
r-x1015读+执行
r--1004只读
---0000无权限
  • rw-r--r-- = u(6)+g(4)+o(4) = 644
  • rwxr-xr-x = 7+5+5 = 755
  • rwxrwxrwx = 777（所有用户最大权限）
补充：8421 来自 BCD 码/二进制位权（8、4、2、1）；本课只需掌握 r=4、w=2、x=1 的换算。

七、chmod：修改权限 ★

7.1 基本要求

  • 修改权限需要管理员权限：sudo chmod ... 文件。
  • 语法：sudo chmod [方式] 文件。

7.2 方式一：字符方式

chmod [u/g/o/a][+/-/=][r/w/x] 文件
写法含义
u+w给所有者添加写权限
g+w给所属组添加写权限
u-w去掉所有者写权限
o+x给其他用户添加执行权限
a=rwx所有用户设为 rwx
u+x,o-x多个操作逗号分隔

课堂演示：大 A 目录原本 rwx r-x r-x（755）；sudo chmod g+w A → rwx rwx r-x；sudo chmod u-w A → r-x rwx r-x；sudo chmod 777 A → 全部 rwx。

7.3 方式二：数字方式

sudo chmod 数字组合 文件（三位数依次表示 u、g、o）

教材例题：将 hello.c 设为：所有者 rwx(7)、同组 rw-(6)、其他 --x(1) → sudo chmod 761 hello.c，之后 ll 验证为 rwx rw- --x。

7.4 补充

  • 普通文件新建后可读写；脚本文件（.sh）创建后需加执行权限才能运行：sudo chmod +x 脚本.sh。
  • 教材参考页：135、136、137 页，图/例 5.2.2、5.2.3（约第 22、23 页例题）。

八、ln：链接文件 ★

8.1 格式

类型命令说明
硬链接ln 原文件 硬链接名基于原文件创建
软链接ln -s 原文件 软链接名-s = soft（software）

8.2 硬链接（Hard Link）

  • 类似“复制”，本质是同一 inode（磁盘节点） 增加一个入口/文件名。
  • 课堂验证：创建后文件类型仍为普通文件 -；时间戳与原文件一致；删除原文件后硬链接不受影响；权限格式一致。

8.3 软链接（Soft Link）

  • 类似 Windows 桌面快捷方式。
  • 命令加 -s；文件类型显示为 l 且有 -> 原文件；时间戳是创建时刻；删除原文件后软链接失效（红色/黑底显示）。

8.4 软链接 vs 硬链接对比

对比项硬链接软链接
命令ln 原 名ln -s 原 名
ll 首字符普通文件 -链接文件 l
时间戳与原文件一致创建时刻
指向同一 inode 的不同入口记录原文件路径
删除原文件后不受影响失效（红/黑显示）
类比同一部电影的两个名字Windows 快捷方式

十、易错点复盘 ★

  1. cp 目录忘加 -r → 报错；mv 目录不需要参数。
  2. rm 目录忘加 -r → 删不掉；rm -rf 危险，务必确认目标。
  3. r 读、w 写、x 执行，别把读和写当成一回事。
  4. 权限顺序固定：u、g、o 三组，每组 rwx 不变。
  5. 数字换算：r=4、w=2、x=1；761 = u(7) g(6) o(1)，顺序别写反。
  6. 硬链接删原文件还在；软链接（ln -s）删原文件就失效。
  7. 改权限要 sudo。
  8. 脚本要加 x 才能运行。
  9. 创建链接/文件避免同名冲突。

十一、课堂操作复盘（标准流程）

  1. 移动文件：mv file1 /home/DIR2/ → 源目录 ls 确认没了 → 目标 ls 确认到了 → ll 看时间戳保留。
  2. 移动目录：mv /home/DIR1 /home/DIR2/（无需 -r）→ 两边验证。
  3. 删除文件：rm file1（提示输入 y；权限不够加 sudo）。
  4. 删除目录：sudo rm -r dir2 → ls 验证。
  5. 查看类型/权限：ll 看首字符和 9 位权限。
  6. 字符方式改权限：sudo chmod g+w A、sudo chmod u-w A。
  7. 数字方式改权限：sudo chmod 761 hello.c → ll 验证 rwx rw- --x。
  8. 硬链接：ln hello.c hhello.c → ll 验证；删原文件后硬链接仍在。
  9. 软链接：ln -s hello.c shello.c → ll 验证类型 l；删原文件后软链接失效。
  10. 网络：ifconfig 看网卡/IP/丢包；ping 目标IP 测连通。

  1. 复制目录要 cp -r；移动目录直接 mv，不用加 -r。

  5. r 可读、w 可写、x 可执行。

  9. 硬链接是同一 inode 的另一个入口，时间戳一致、删原文件不受影响；软链接类似快捷方式、类型为 l、删原文件后失效。
  10. ping 测试网络连通性；ifconfig 查看网卡名、IP、收发字节、丢包率等。

  3. 处理器种类与选择：MPU（中高端数据处理）、MCU（低端控制，如单片机）、DSP（数字信号处理）、SoC（片上系统，手机等）、SOPC（可编程片上系统）；按实际需求场景和性能选择——成本低选 MCU，处理量大选 MPU/DSP，集成度高选 SoC/SOPC。
  4. 冯诺依曼 vs 哈佛：冯诺依曼指令与数据共用一条总线、互相冲突效率低（一个门）；哈佛存储与总线分开、互不影响效率高（前门后门）；现代 MCU/ARM 普遍用哈佛（改进型）。

八、易错点复盘 ★

  1. cp/rm 操作目录要加 -r，mv 不需要。
  2. 改权限要 sudo；chmod 777 权限最大，慎用于系统文件。
  3. tar 参数：创建 c、释放 x、查看 t、压缩 z，别把 c/x 用反。
  4. .tar 是打包，gz 才是压缩。
  5. vi 三模式切换：i 进插入、Esc 回标准、Shift+: 进底行；插入模式不能直接进底行模式。
  6. 不保存退出 :q!，保存退出 :wq，别记反。
  7. 改文件前先 chmod 保证可写。
  8. 桥接模式要求同网段才能互通；改 IP 后 ifconfig 验证。
  9. ping 不通先查防火墙、IP、是否同网段。

  • ls -l 中 6 行 70 字节：1 字节（Byte/B）= 8 位（bit/b），注意大 B 是字节、小 b 是位。

  • 全称 GNU C Compiler（GNU 编译器集合，通常叫 GCC）。

  • 跨平台：Windows 上 Code::Blocks 用的就是 gcc，换到 Linux 内核完全不同它仍可用。

单文件编译

gcc hello.c -o hello # -o 后跟输出文件名（output） ./hello # 执行：./ 后不加空格，直接跟文件名
  • -o 含义是 output，指定生成的可执行文件名（不能起成 .c）。
  • 不加 -o 时默认生成 a.out。
  • 编译后文件会变大（如 70 字节 → 约 15 KB），因为把库等内容链接了进来。
  • hello world 只在终端回显，不像 Dev-C++ 单独弹窗。

五、编译的四个阶段 ★（本课核心）

阶段名称参数输入输出做了什么
①预处理-E.c.i展开头文件、宏替换、去注释、条件编译
②编译-S.i.s语法/语义分析，生成汇编代码
③汇编-c.s.o把汇编翻译成机器码
④链接（-o）.o + 库可执行文件把多个目标文件与库连成可执行程序
顺序不可变：一定是 ① → ② → ③ → ④。IDE 里点一下“编译运行”看似一瞬间，底层依次做完了这四步。

逐阶段演示

gcc -E hello.c -o hello.i # ① 预处理 → .i gcc -S hello.i -o hello.s # ② 编译 → .s（汇编） gcc -c hello.s -o hello.o # ③ 汇编 → .o（目标文件） gcc hello.o -o hello # ④ 链接 → 可执行文件 ./hello # ⑤ 执行
  • .i：头文件被展开、宏被替换、注释被删，但仍是 C 语言。
  • .s：和 C 结构完全不同，一行一行，可见 mov、register、offset 等。C 后缀 .c，汇编后缀 .s。
  • .o：二进制机器码，用 cat/vi 打开是乱码——这正是源码不直接暴露的原因（企业靠“编译后不开源”保护知识产权，反编译也难还原）。
  • 把四步合成一条 = 日常的 gcc hello.c -o hello。

六、多文件工程与 make / Makefile ★

6.1 为什么要 Makefile

  • 一个工程常有 main.c、input.c、add.c、lcd12864.c 等十几个 .c 文件。
  • 若每次都用 gcc a.c b.c c.c ... -o main：命令又长又易错，改一个文件还得全部重编，低效且易错。
  • 解决：用 make 工具 + Makefile 文件统一管理工程。

6.2 Makefile 的三条硬规则

规则要求
文件名Makefile（M 必须大写；也可 makefile）
位置与工程源文件放在同一个文件夹
缩进命令行的缩进必须用 Tab，不能用空格

6.3 书写格式

main: main.o input.o add.o gcc main.o input.o add.o -o main main.o: main.c gcc -c main.c -o main.o input.o: input.c gcc -c input.c -o input.o add.o: add.c gcc -c add.c -o add.o clean: rm -f *.o main
  • 格式 = 目标: 依赖，下一行（Tab 缩进）是命令。
  • 理解方式：倒推——想要 main，就得先有 .o；想要 .o，就得有对应 .c。
  • clean：make clean 执行 rm -f *.o main，只删中间对象与可执行文件，保留源码 .c / .h / Makefile。

6.4 make 解决的三件事

  1. 工程没编译过：所有 .c 全部编译。
  2. 只改了个别 .c：只重新编译被改动的那个（10 个改 1 个只编 1 个，省时间）。
  3. 头文件被改：找到引用了该头文件的 .c 重新编译，避免全量重编。
课堂现象：make 后能看到 4 条编译信息；ls 多出若干 .o 与可执行文件；make clean 后恢复成“3 个 .c + 2 个 .h + Makefile”。

Samba ★Linux ↔ Windows让 Windows 直接访问 Linux 的共享目录（本课重点）
为什么讲 Samba：Ubuntu 跑在 VMware 虚拟机里，虚拟机又跑在 Windows 里——典型的跨平台环境，Samba 就是打通两平台文件共享的桥梁。

3.2 C/S 架构

  • C = Client（客户端）：提出请求的一方；S = Server（服务器）：提供服务、响应请求的一方。
  • 生活类比：选课系统（白天抢课卡、半夜好登录）、双 11（并发太大卡单）、蓝桥杯（教师机当服务器、考生机当客户端下题）。

四、Samba 服务器配置 ★（七步流程）

前提：所有搭建用命令行完成，且虚拟机必须联网——否则第 1 步 apt-get 装不上，后面全做不了。

第 1 步：安装 Samba

sudo apt-get install samba samba-common
  • apt-get install 安装软件包；samba 是服务程序，samba-common 是公共组件。
  • 会输出进度、版本号；若已是最新会提示 already the newest version。

第 2 步：创建共享文件夹

mkdir /home/samba # 在 home 下创建共享文件夹 chmod 777 /home/samba # 给最大权限（否则客户端无权访问）
  • 必须改权限：就像门没有钥匙进不去，权限不够客户端无法上传/下载。

第 3 步：创建账户并设置密码

sudo useradd -m samba # 创建系统账户 sudo smbpasswd -a samba # 为 Samba 账户设置专用密码
  • Samba 有独立密码体系：要用 smbpasswd 单独设密码，与系统登录密码分开。
  • -a 表示添加账户；输密码时不显示字符（安全机制）。

第 4 步：修改配置文件 ★

sudo chmod 777 /etc/samba/smb.conf # 先保证可写，否则 vi 保存不了 sudo vi /etc/samba/smb.conf
  • 配置文件在 /etc/samba/ 下，名 smb.conf。
  • 命令模式用 nG 跳到第 n 行；用 :set nu 显示行号。
  • 在文件末尾追加共享段（示意）：
[samba] # 方括号里是共享名（=共享文件夹名） comment = samba share path = /home/samba # 共享目录的绝对路径 browseable = yes # 是否可被浏览 writable = yes # 是否可写 public = yes # 是否公开（公共） available = yes # 是否启用 valid users = samba # 允许访问的账户
关键字段：path（路径）、browseable（可浏览）、writable（可写）、public（公开）、available（可用）。权限要“给开”，客户端才能读写。

第 5 步：重启服务

sudo service smbd restart # 或 sudo systemctl restart smbd
  • 改完配置必须重启服务才生效；服务进程名是 smbd。

第 6 步：保证网络通畅

ifconfig # 查 Ubuntu 虚拟机 IP（如 192.168.43.37） ipconfig # 在 Windows 的 cmd 中查宿主机 IP ping 192.168.43.37 # 两边互相 ping，能通即 OK
  • 只有两系统在同一网段、能 ping 通，Windows 才能连上 Samba。

第 7 步：Windows 端登录测试

  1. Win + R 打开“运行”框。
  2. 输入 \\192.168.43.37（\\ + 服务器 IP）回车。
  3. 弹出登录框，输入 Samba 账户名与密码。
  4. 登录成功后看到共享目录，直接拖拽上传/下载文件。
一句话记：装包 → 建目录 → 建账户 → 改配置 → 重启 → 通网 → 登录。

五、Shell 编程基础

5.1 Shell 是什么

  • Shell（外壳）：介于操作系统内核与用户之间的桥梁。
  • 用户输入的每条命令（ls、mkdir、history 等）都经 Shell 传给内核，内核执行后由 Shell 把结果反馈给用户。
  • 双重身份：① 命令解析器（解释执行单条命令）；② 高级程序设计语言（有变量、关键字、控制语句，可把多条命令组织成脚本）。

5.2 Shell 的分类

Korn Shellksh兼容 sh 并增强
Bourne Again ShellbashUbuntu/Linux 默认，功能最强 ★
  • 查看当前 Shell：echo $SHELL（通常显示 /bin/bash）。

6.1 创建脚本

  1. 脚本内容示例：

七、Shell 变量 ★

7.1 命名规则（与 C 相同）

  • 由字母、数字、下划线组成。
  • 只能以字母或下划线开头，不能以数字开头。
  • 不能使用 Shell 的关键字（保留字）。

7.2 变量分类

类别说明示例
环境变量保存系统状态/环境参数HOME、HISTSIZE、LOGNAME、SHELL
位置参数变量传递脚本参数、判断命令返回值$0、$1~$9、$*、$#、$?
用户自定义变量脚本中自己定义使用A=3、B=$A
引用变量必须加 $（如 echo $A），这一步叫变量替换/变量引用，非常重要。

7.3 赋值与使用

A=3 # 等号两边不能有空格！ B="hello world" # 值含空格用双引号 echo $A # 打印变量 A 的值 C=$B # 变量可递进赋值 echo "hello, $C" # 变量可嵌入字符串
  • 等号两侧不能有空格（A = 3 会报错）。
  • 值中有空格时用双引号括起来。
  • 变量可“链式”赋值（C=$B、B=$A），值依次传递。
  • 变量可作为字符串的一部分，类似 C 中 printf("年龄为%d", age) 的格式化效果。

7.4 变量的数据计算

A=2 expr 8 + $A # 结果 10（注意运算符两侧要有空格） B=10 let C=5+B # 结果 15 echo $C
  • 两条指令：expr 与 let。
  • expr 做算术/比较，变量要加 $，运算符两侧留空格；let 直接做整数运算并赋值。
  • 这些也可在终端直接执行——Shell 既是命令解析器，也是编程语言。

六、if 条件语句

6.1 三种形式

# ① 单分支 if [ 条件 ]; then 命令 fi # ② 双分支 if [ 条件 ]; then 命令1 else 命令2 fi # ③ 多分支 if [ 条件1 ]; then 命令1 elif [ 条件2 ]; then 命令2 else 命令3 fi
  • 与 C 的区别：Shell 用 then 引出语句、用 fi 结束；C 用 { }。
  • elif 在 Shell 中是一个单词（不是 else if）。
  • if 与 fi 必须成对出现。

6.2 例子：判断普通文件

#!/bin/bash if [ -f "$1" ]; then echo "$1 是一个普通文件" else echo "$1 不是一个普通文件" fi

6.3 例子：比较两个数

#!/bin/bash N1=10 N2=20 if [ $N1 -eq $N2 ]; then echo "相等" elif [ $N1 -gt $N2 ]; then echo "N1 大于 N2" else echo "N1 小于 N2" fi

7.1 select：交互式菜单

select var in A B C D do echo "你的回答是 $var" break done
  • 特点：自动生成 1) 2) 3)… 编号菜单，自动读取用户输入并赋给变量。
  • 不需要自己写 echo 菜单、不需要写 read、不需要手动赋值。
  • 适合做点菜式菜单：输入编号，自动映射到对应选项。
  • 用 break 退出，否则会一直循环。

7.2 case：多分支匹配

case "$1" in 1) echo "你选了 1" ;; 2) echo "你选了 2" ;; *) echo "输入不在 1~4 范围内" ;; esac
  • 类似 C 的 switch-case：把值与各分支模式依次比对。
  • ;; 表示一个分支结束（两个分号，别漏）。
  • * 是默认分支（相当于 default）。
  • esac 是 case 的倒写，表示结束。

八、循环语句 ★

8.1 for：带列表

for country in 中国 美国 英国 日本 do echo $country done
  • 依次从列表中取值，每取一个执行一次循环体。
  • 列表可以是字符串、数字、文件名通配符（如 for f in *.c）。

8.2 for：不带列表 / C 风格

# 方式一：自己生成列表 for i in 1 2 3 do echo "观点$i" done # 方式二：C 风格三段式 for ((i=1; i<=100; i++)) do sum=$((sum + i)) done
  • “不带列表”不是没有列表，而是由用户/脚本自己创建列表（或使用 C 风格三段式）。
  • C 风格：for ((初始值; 条件; 步长))，与 C 的 for 几乎一致。

8.3 while：条件为真就循环

i=1 sum=0 while [ $i -le 100 ] do sum=$((sum + i)) i=$((i + 1)) done echo $sum
  • 先判断条件，成立才执行循环体；不成立一次都不执行。
  • 课堂例子：求 1~100 的和；求 1~100 的奇数和时，步长改为 i=$((i+2))。

九、break 与 continue

语句作用
break跳出整个循环，不再执行后续轮次
continue跳过本次循环剩余语句，直接进入下一轮
for i in 2 3 4 5 do if [ $i -eq 4 ]; then continue # 跳过 4，不打印 fi echo $i # 输出 2 3 5 done
  • 课堂现象：输出 2 3 5，因为遇到 4 时 continue 跳过了 echo。
  • 若用 break，则遇到 4 后整个循环直接结束。

  • 对应指令 rmdir，只能删除空目录（和指令行为一致）。

6.3 getcwd：获取当前工作目录

/* getcwd_demo.c */ #include <stdio.h> #include <unistd.h> #include <errno.h> #include <string.h> int main(void) { char buf[256]; if (getcwd(buf, sizeof(buf)) == NULL) { printf("getcwd error: %s\n", strerror(errno)); return -1; } printf("current dir: %s\n", buf); return 0; }

/* stat_demo.c */ #include <stdio.h> #include <sys/stat.h> #include <sys/types.h> #include <errno.h> #include <string.h> int main(int argc, char *argv[]) { struct stat st; int ret; if (argc < 2) { printf("usage: %s <path>\n", argv[0]); return -1; } ret = stat(argv[1], &st); /* 取地址传入结构体 */ if (ret == -1) { printf("stat error: %s\n", strerror(errno)); return -1; } if (S_ISDIR(st.st_mode)) printf("%s: is a directory\n", argv[1]); else if (S_ISREG(st.st_mode)) printf("%s: is a regular file\n", argv[1]); else if (S_ISLNK(st.st_mode)) printf("%s: is a symbolic link\n", argv[1]); else if (S_ISCHR(st.st_mode)) printf("%s: is a character device\n", argv[1]); else if (S_ISBLK(st.st_mode)) printf("%s: is a block device\n", argv[1]); else if (S_ISFIFO(st.st_mode)) printf("%s: is a fifo\n", argv[1]); else if (S_ISSOCK(st.st_mode)) printf("%s: is a socket\n", argv[1]); printf("size = %ld bytes, links = %lu\n", (long)st.st_size, (unsigned long)st.st_nlink); return 0; }

7.1 access：检查文件是否存在/权限

#include <unistd.h> int access(const char *pathname, int mode);
mode 常量数值检查什么
F_OK0文件是否存在
X_OK1是否有执行权限
W_OK2是否有写权限
R_OK4是否有读权限
  • 记忆：0 存在、1 执行、2 写、4 读，正好对上 rwx = 421。
  • 成功返回 0，失败返回 -1。
  • 多个权限可以按位或：access("f", R_OK | W_OK)。

7.2 creat：创建文件

#include <fcntl.h> #include <sys/stat.h> int creat(const char *pathname, mode_t mode);
  • 成功：返回文件描述符；失败：-1。
  • 等价于 open(pathname, O_WRONLY | O_CREAT | O_TRUNC, mode)。
  • 创建完文件就是"打开"状态，用完必须 close，否则占用系统资源（老师比喻：教室开门不关，资源一直占着）。
  • 文件已存在时，creat 会清空原内容（O_TRUNC）——这是坑，见易错点。
/* creat_demo.c —— 对应课本"打印 fd"的例子 */ #include <stdio.h> #include <sys/types.h> #include <sys/stat.h> #include <fcntl.h> #include <unistd.h> #include <errno.h> #include <string.h> int main(void) { int fd = -1; fd = creat("./test.txt", 0777); /* 0777：属主/属组/其他全 rwx */ if (fd < 0) { printf("creat error: %s\n", strerror(errno)); return -1; } printf("ok: %d\n", fd); /* 课堂上输出 ok: 3 */ close(fd); /* 一定要关 */ return 0; }

7.3 open：打开/创建文件 ★

#include <fcntl.h> int open(const char *pathname, int flags); /* 不带创建 */ int open(const char *pathname, int flags, mode_t mode); /* 带 O_CREAT 时必须给 mode */

flags 常用标志：

标志含义说明
O_RDONLY只读三者只能选一个
O_WRONLY只写—
O_RDWR读写—
O_CREAT不存在则创建需配合 mode
O_EXCL与 O_CREAT 连用文件已存在则失败，防止覆盖
O_TRUNC打开时清空长度截为 0
O_APPEND追加每次写前把读写位置移到文件末尾

组合示例：

需求写法
读写打开，不存在就创建O_RDWR | O_CREAT
创建新文件，已存在就报错O_WRONLY | O_CREAT | O_EXCL
追加写，不存在就创建O_WRONLY | O_CREAT | O_APPEND
打开并清空（等价 creat）O_WRONLY | O_CREAT | O_TRUNC

O_CREAT | O_EXCL 就是"安全创建"：只有文件真不存在才成功，避免误覆盖已有文件。

7.4 close：关闭文件

int close(int fd);
  • 成功 0，失败 -1。
  • 关闭后 fd 被释放，可被后续 open 复用。
  • 程序退出时内核会自动回收，但显式 close 是好习惯（尤其循环里打开大量文件时）。

7.5 read：读数据

#include <unistd.h> ssize_t read(int fd, void *buf, size_t count);
返回值含义
> 0实际读到的字节数（可能小于 count）
0已读到文件末尾（EOF）
-1出错（看 errno）

关键：read 返回的不一定是你请求的字节数，必须用返回值当有效长度，不能假设读满了。

7.6 write：写数据

ssize_t write(int fd, const void *buf, size_t count);
  • 返回实际写入的字节数；-1 表示失败。
  • write 是系统调用，不经过 printf 的用户态缓冲区；printf 有缓冲，混用时注意 fflush(stdout)。

7.7 lseek：移动读写位置（扩充）

#include <unistd.h> off_t lseek(int fd, off_t offset, int whence);
whence基准
SEEK_SET文件开头
SEEK_CUR当前位置
SEEK_END文件末尾
  • 返回新的偏移量，失败 -1。
  • 常用：lseek(fd, 0, SEEK_END) 求文件大小；lseek(fd, 0, SEEK_SET) 回到开头重读。
  • 老师课上提到"文件读写指针"可以调位置，lseek 就是干这个的，和标准 I/O 的 fseek 对应。

7.8 unlink：删除文件

#include <unistd.h> int unlink(const char *pathname);
  • 对应指令 rm。成功 0，失败 -1。
  • 它删除的是目录项（文件名），并让 inode 的硬链接计数 −1；计数减到 0 时，数据块才真正释放。
  • 所以：有硬链接的文件，unlink 掉一个名字，文件内容还在；删软链接只删链接本身，不动源文件。

8.2 例 2：判断存在 → 打开，否则创建

/* exist_open.c —— 课本 5.3.4 例 */ #include <stdio.h> #include <unistd.h> #include <fcntl.h> #include <errno.h> #include <string.h> int main(int argc, char *argv[]) { int fd, ret; if (argc < 2) { printf("usage: %s <file>\n", argv[0]); return -1; } ret = access(argv[1], F_OK); /* 检查是否存在 */ if (ret == -1) { /* 不存在 → 创建 */ printf("%s not exist, create it\n", argv[1]); fd = creat(argv[1], 0666); if (fd < 0) { perror("creat"); return -1; } printf("creat ok, fd = %d\n", fd); close(fd); } else { /* 存在 → 打开 */ printf("%s exists, open it\n", argv[1]); fd = open(argv[1], O_RDWR); if (fd < 0) { perror("open"); return -1; } printf("open ok, fd = %d\n", fd); close(fd); } return 0; }

逻辑主线：先问"有没有"（access），再决定"开还是建"（open / creat）。

8.3 例 3：存在就读 200 字节，不存在就创建并写

/* read_or_write.c */ #include <stdio.h> #include <unistd.h> #include <fcntl.h> #include <string.h> #include <errno.h> int main(int argc, char *argv[]) { int fd, ret; char rbuf[4096]; /* 读缓冲：4096 字节 */ char wbuf[256]; /* 写缓冲：256 字节 */ if (argc < 2) { printf("usage: %s <file>\n", argv[0]); return -1; } if (access(argv[1], F_OK) == 0) { /* 文件存在 → 读 */ fd = open(argv[1], O_RDONLY); if (fd < 0) { perror("open"); return -1; } ret = read(fd, rbuf, 200); /* 只读 200 字节 */ if (ret < 0) { perror("read"); close(fd); return -1; } rbuf[ret] = '\0'; /* 补字符串结束符，才能用 %s 打印 */ printf("read %d bytes:\n%s\n", ret, rbuf); close(fd); } else { /* 文件不存在 → 创建并写 */ fd = creat(argv[1], 0666); if (fd < 0) { perror("creat"); return -1; } printf("input some words: "); if (scanf("%255s", wbuf) != 1) { close(fd); return -1; } /* 存进内存 */ ret = write(fd, wbuf, strlen(wbuf)); /* 内存 → 文件 */ if (ret < 0) { perror("write"); close(fd); return -1; } printf("write %d bytes ok\n", ret); close(fd); } return 0; }

老师强调的点：scanf 只是把内容读进内存（wbuf），真正落盘要靠 write 把内存内容写进 fd。

8.4 例 4：文件复制（本课最完整的一个）

思路相当于"两杯水交换"要一个中间杯子：A 文件 → 中间缓冲 buf → B 文件，循环搬运直到读完。

/* mycp.c —— 实现 cp 的核心逻辑 */ #include <stdio.h> #include <unistd.h> #include <fcntl.h> #include <string.h> #include <errno.h> int main(int argc, char *argv[]) { int fd_src, fd_dst, ret; char buf[1024]; /* 中间缓冲：1KB */ if (argc < 3) { printf("usage: %s <src> <dst>\n", argv[0]); return -1; } fd_src = open(argv[1], O_RDONLY); /* 源文件：只读 */ if (fd_src < 0) { perror("open src"); return -1; } fd_dst = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0666); /* 目标：写+建+清空 */ if (fd_dst < 0) { perror("open dst"); close(fd_src); return -1; } while ((ret = read(fd_src, buf, sizeof(buf))) > 0) { if (write(fd_dst, buf, ret) != ret) { /* 必须写满 ret 字节 */ perror("write"); close(fd_src); close(fd_dst); return -1; } } if (ret < 0) perror("read"); /* 循环因出错退出 */ close(fd_src); close(fd_dst); printf("copy done\n"); return 0; }

编译运行：

gcc mycp.c -o mycp ./mycp a.txt b.txt diff a.txt b.txt # 无输出即复制成功

十、易错点复盘 ★

  1. open 带 O_CREAT 却忘记给第三个参数 mode —— 编译不报错，运行时生成的文件权限是随机垃圾值（其实是栈上残值），必须写 open(path, O_CREAT|O_WRONLY, 0666)。
  2. umask 会"暗中削权限" —— creat("f", 0777) 在默认 umask 022 下得到的是 0755，不是 0777。实际权限 = mode & ~umask。想验证：umask 查看，umask 000 临时清零。
  3. 目录用 creat/open 打开会失败 —— 目录不能用普通文件方式读写，要 opendir/readdir。
  4. read 返回值当成"读满了" —— 返回值才是有效长度，且 0 表示 EOF，-1 才是错误。循环要写 while ((n = read(...)) > 0)。
  5. write 没写满就不管了 —— 严格写法是判断 write 返回值是否等于 ret，不等要重试或报错。
  6. creat 会清空已有文件 —— creat = O_TRUNC，想在原文件后追加要用 O_APPEND。
  7. 字符串缓冲区没补 '\0' 就用 printf("%s") —— read 不会自动加结束符，必须 buf[n] = '\0'。
  8. stat 和 fstat 混用 —— fstat 需要已打开的 fd；目录只能用 stat。
  9. close 忘写 —— 短程序看不出问题，长程序/循环里会耗尽 fd（默认上限 1024，报 Too many open files）。
  10. errno 要紧接着用 —— 中间又调了别的函数，errno 可能被覆盖；要么立刻打印，要么先存起来。
  11. 返回值判断写成 if (fd) —— fd 为 0 时也是合法描述符（虽然标准流占用了 0/1/2），判断失败要用 < 0，不要用 !fd。
