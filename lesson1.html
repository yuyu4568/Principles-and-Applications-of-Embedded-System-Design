二、嵌入式系统的定义 ★

标准定义：嵌入式系统是以应用为中心、以计算机技术为基础、软硬件可裁剪，适用于应用系统对功能、可靠性、成本、功耗等有严格要求的专用计算机系统。

关键词拆解

  • 以应用为中心：按具体任务定制（如空调控制器只负责温控）。
  • 以计算机技术为基础：本质仍是计算机系统。
  • 软硬件可裁剪：硬件按需减少外设，软件按需裁剪模块。
  • 专用计算机系统：与通用 PC 相对，通常只完成特定功能。

主要特点（扩充）

特点说明
专用性面向特定应用定制
可裁剪性软硬件均可按需增删
实时性多数系统要在规定时间内响应（如安全气囊毫秒级触发）
资源受限内存、Flash、功耗、体积、成本受约束
高可靠性长期运行、环境恶劣仍需稳定
软硬件紧耦合需软硬件协同设计

vs 通用计算机（扩充）

维度嵌入式系统通用计算机
定位专用功能通用任务
软硬件可裁剪、资源受限资源丰富、可扩展
功耗/体积低功耗、小体积功耗和体积较大
操作系统裁剪定制（Linux、RTOS，甚至裸机）Windows、macOS 等
开发调试交叉开发、烧录调试本机开发调试
升级维护较难，需专门工具方便
常见考法：填空“以___为中心、以___为基础、软硬件___”，或简答“嵌入式系统的特点”。

三、嵌入式系统的组成 ★

三大部分（课堂强调）

  • 硬件层：核心是处理器（芯片），如 ARM、8051 内核 MCU；外围包括内存、USB、VGA/HDMI、投影、传感器等。
  • 嵌入式操作系统：精简、可裁剪，如嵌入式 Linux、FreeRTOS。
  • 嵌入式软件：面向具体应用的程序，下载/烧录到目标硬件运行。

更完整的四层结构（扩充）

层次内容作用
应用层应用程序实现具体业务功能
操作系统层内核、文件系统、网络协议栈管理资源、提供系统服务
中间层BSP / HAL / 驱动屏蔽硬件差异，统一接口
硬件层CPU、存储、I/O、外设、总线系统物理基础
理解要点：课堂“三部分”是宏观分类；教材的“中间层”属于软硬件之间的适配层，不必对立记忆。

硬件核心部件（扩充）

  • CPU/处理器：MCU、MPU、DSP、SoC（见第十四章）。
  • 存储器：RAM（运行程序）、ROM/Flash（固件）。
  • I/O 与总线：GPIO、UART、SPI、I2C、CAN、USB、以太网。
  • 电源与时钟：供电电路、晶振。

四、ARM 与嵌入式微处理器 ★

4.1 两大主流架构

架构典型设备指令集特点
x86PC、笔记本、服务器CISC 复杂指令集性能强、功耗高、生态成熟
ARM手机、平板、嵌入式设备RISC 精简指令集低功耗、低成本、应用广
扩充：手机对功耗、散热极敏感，ARM 以低功耗见长；近年 ARM 也开始进入笔记本/服务器（如 Apple M 系列）。

4.2 ARM 的三种含义

  1. 公司名称：ARM 公司（Advanced RISC Machines，1990 年成立）。
  2. 微处理器的统称：基于 ARM 内核的处理器。
  3. 技术名称：ARM 架构本身（指令集与内核规范）。

4.3 商业模式：卖 IP 核

  • ARM 不直接造芯片，研发并授权 IP 核（知识产权核）。
  • IP 核是“芯片的架构与核心设计”，不是网络 IP 地址。
  • 收费方式：授权许可费 + 版税。

4.4 IP 核三种形态（扩充）

类型提供形式灵活性
软核 Soft CoreHDL 代码（Verilog/VHDL）高，可综合重配置
固核 Firm Core综合网表/布局约束中，跨工艺需重优化
硬核 Hard Core已定版图、工艺固定低，性能确定不可改

4.5 芯片产业链（扩充）

IP 授权（ARM） ↓ 芯片设计（高通/三星/联发科等） ↓ 晶圆代工（台积电、中芯国际等） ↓ 封装测试 → 渠道零售 → 终端用户

4.6 8051 背景（扩充）

  • 主流单片机（STC、AT89 等）内核是 8051；51/52 区别主要在片内 RAM 大小。
  • 4 个 I/O 口：P0 ~ P3，每口 8 位，用于 LED、按键、中断、串口实验。
  • 8051 是 8 位处理器；STM32 是 32 位处理器（寄存器更多、更复杂）。
  • 32 位处理器直接查手册开发效率低，通常用库函数/驱动库开发（标准库、HAL 库）。
防静电：人体静电瞬时放电可达上万伏，可能击穿芯片；芯片使用防静电袋包装，操作注意防静电手环、接地。

五、ARM 系列与架构对比 ★

5.1 ARM 系列演进

系列架构特点
ARM7冯·诺依曼架构成熟大批量、3 级流水线、RISC、低功耗（约 130 MIPS）
ARM9 / ARM10 / ARM11哈佛架构总线路分离，流水线级数更高，效率更高
Cortex 系列按应用细分 A/R/MSTM32 采用 Cortex-M

5.2 Cortex 三大系列（扩充）

系列目标典型应用
Cortex-A高性能应用处理器手机 SoC、平板、树莓派
Cortex-R硬实时、高可靠汽车刹车/气囊、硬盘控制器
Cortex-M低功耗单片机STM32、GD32 等 MCU、物联网
扩充——Thumb 指令集：ARM 的 16 位 Thumb 指令、16/32 位混合的 Thumb-2 指令，在代码密度与性能间取得平衡，Cortex-M 广泛使用。

5.3 冯·诺依曼架构

  • 组成：运算器、控制器、存储器、输入、输出；CPU = 运算器 + 控制器。
  • 特点：程序与数据共用一条总线，可能拥堵；结构简单、成本低。

5.4 哈佛架构

  • 特点：程序与数据总线分离，可并行访问，效率更高。
  • 类比：教室两个门，一个进一个出，比单门快。

5.5 流水线（扩充）

指令执行分“取指 → 译码 → 执行 → 写回”等阶段，多级流水线让多条指令重叠执行。ARM7 为 3 级，ARM9 为 5 级，级别越高吞吐越快。

5.6 RISC vs CISC（扩充）

维度RISC（ARM）CISC（x86）
指令少而精、定长多而复杂、变长
执行多单周期，适合流水线复杂指令微码实现
功耗低高
依赖靠编译器优化硬件承担更多

六、嵌入式系统开发流程 ★

6.1 三大开发

嵌入式系统开发包括：总体开发、硬件开发、软件开发。

6.2 详细流程（扩充）

系统定义与需求分析（产品经理） ↓ 需求规格说明书 SRS ↓ ┌── 硬件开发 ──┐ ┌── 软件开发 ──┐ │ 原理图设计 │ │ 概要/详细设计 │ │ PCB 设计/制板 │ │ 编码 │ │ 硬件调试 │ │ 编译/单元测试 │ └─────┬────────┘ └─────┬────────┘ └── 软硬件联调（验证测试）──┘ ↓ 验收；不合格返回修改（闭环大循环） ↓ 交付与维护
  • 产品经理：立项前与甲方对接、调研需求，明确功能/性能/规格，避免反复改动。
  • 验收：软硬件适配跑通才算合格；不符合需求返回修改，形成大循环。
  • 流程图是重点：顺序步骤用流程框（矩形），判断条件用判断框（菱形），对应 if、if-else、switch-case。

6.3 开发模型（扩充）

模型特点适用
瀑布阶段顺序推进需求明确的简单项目
迭代/增量分块开发逐步完善需求易变的中大型项目
螺旋需求→设计→原型→风险评估循环高风险项目

七、自顶向下 vs 自底向上 ★

方法思路类比优缺点
自顶向下 Top-Down按模块拆分，先总体后细化装修教室：讲台/课桌/照明/投影单模块修改影响小、易维护
自底向上 Bottom-Up从底层逐层搭建盖房子：先打地基再砌墙底层出问题返工成本高

课堂案例复盘

  • 桌椅摆放：不合理只改桌椅模块，不动讲台黑板。
  • 照明：灯横向摆，灯在身后影子遮作业本；纵向摆阴影更小。
  • 盖房子：地基不牢（2 米而非 7 米），上层全出问题，返工层层拆。
扩充——模块化原则：高内聚（模块内功能紧密相关）、低耦合（模块间依赖少），便于开发、测试、替换、复用。

结论：实际二者交替结合，整体以自顶向下为主体。

八、交叉编译 ★

8.1 为什么要交叉编译

  • 目标设备（ARM）资源有限，不在目标板上开发。
  • x86 上编译的程序不能直接在 ARM 上运行（指令集、ABI 不同）。
  • 解决：在宿主机 Host 上用交叉编译器生成在目标机 Target（ARM）上运行的代码。
编译方式宿主机目标机工具
本机编译x86 PCx86 PCgcc（本地）
交叉编译x86 PC（开发机）ARM 等嵌入式目标交叉编译器

8.2 交叉工具链构成（扩充）

组件作用
binutils汇编器 as、链接器 ld、objcopy/objdump
GCC 交叉编译器生成目标架构机器码，如 arm-linux-gnueabihf-gcc
C 运行库glibc / musl / uClibc
GDB 调试器远程/模拟调试

工具链前缀解读：arm-linux-gnueabihf-gcc：arm=目标架构，linux=目标系统，gnueabihf=GNU 工具链 + 硬件浮点，gcc=C 编译器。

8.3 典型流程

PC 编写源码 → 交叉编译 → 生成 ARM 可执行文件 （.elf / .bin / .hex）→ 烧录到目标板 → 运行调试

8.4 软件下载方式（扩充）

方式说明
调试器烧录J-Link / ST-Link，通过 JTAG/SWD
串口 ISPUART 引导程序下载（STC、Bootloader）
网络 TFTP/NFS网口取文件，方便反复调试
存储介质SD 卡、U 盘拷贝
扩充——构建系统：用 Makefile 或 CMake 组织编译，一条 make 按依赖关系编译整个工程，避免手动敲多条 gcc 命令。

十、Linux/Ubuntu 基本认知 ★

  • 普通文件、文件夹、设备、网络接口都抽象为“文件”。
  • 设备在 /dev，配置在 /etc，统一了操作接口。

10.2 常用目录（扩充）

10.3 挂载与权限（扩充）

  • 挂载 Mount：把存储设备接入目录树，如 U 盘出现在 /media/用户名/…；命令 mount / umount。
  • 权限：每组文件三组权限（所有者/组/其他）× rwx（读/写/执行）。
  • root：超级用户；sudo 临时提权执行。普通用户日常操作放在 /home。

  • 放大字体 Ctrl+Shift+=，缩小 Ctrl+-。

十一、Linux 指令基础 ★

11.1 基本规则

  • 格式：命令 [选项] 操作对象，命令与对象之间必须有空格。
  • 大小写敏感：ls 有效，LS 无效。
  • Shell：命令解释器 + 脚本编程语言（.sh）。

11.2 课堂演示命令

  • 成功后分配 UID/GID，并在 /home 生成用户目录。
  • 密码用 passwd 用户名 设置；输入时不回显（正常）。

十二、易错点复盘 ★

  1. 命令与对象之间忘加空格，系统无法识别。
  2. Linux 大小写敏感：LS ≠ ls。
  3. 普通用户直接 useradd 权限不足，需 sudo。
  4. 输密码不回显是正常现象。
  5. 虚拟机资源分配过高，拖慢宿主机。
  6. 桥接模式网络图标为问号 = 未联网。
  7. sudo 是单条命令提权，su - 是切换成 root。
  8. rm -rf 危险，删除前确认路径。
  9. 改 /etc 配置前先备份，权限错会导致系统起不来。
  10. Linux 没有“双击盘符”，按路径一层层访问。

十四、嵌入式系统分类与处理器选型（扩充）

14.1 常见处理器分类

类型组成特点典型应用
MCU 单片机CPU+存储+外设集成8051、AVR、STM32家电、工控、传感
MPU 微处理器仅 CPU，外接存储/外设Cortex-A、x86嵌入式 Linux 系统
DSP 数字信号处理器专长大量乘加运算TMS320、SHARC音频、图像、雷达
SoC 系统级芯片多核/多模块集成骁龙、麒麟、苹果 A 系手机、平板、AI 边缘
FPGA硬件电路可编程Xilinx、Altera高速并行、原型验证
MCU vs MPU：MCU 把 CPU、RAM、Flash、外设集成在一个芯片，便宜低功耗适合控制；MPU 只有 CPU，需外接 DDR/存储，性能强但成本功耗高，常跑 Linux。

14.2 选型因素

  1. 性能：主频、MIPS/DMIPS、浮点能力。
  2. 功耗与散热：电池供电选低功耗 MCU。
  3. 外设：UART/SPI/I2C/CAN/USB/以太网。
  4. 存储：片内 Flash/RAM 是否够用。
  5. 开发环境与生态：工具链、库、例程、社区。
  6. 成本与供货：BOM、长期供货、国产替代。

十五、嵌入式操作系统与实时性（扩充）

15.1 三类软件形态

形态说明适用
裸机（前后台）主循环 + 中断，无 OS简单任务、成本极低
RTOS多任务调度、优先级、信号量多任务、实时性较强
嵌入式 Linux含网络、文件系统、GUI功能复杂、资源充足

15.2 实时性

  • 硬实时：必须在截止时间前完成，否则系统失效（安全气囊、刹车）。
  • 软实时：偶尔超时影响体验但不致命（视频卡顿）。

15.3 RTOS 核心机制

  • 任务（Task）：独立执行单元，有优先级。
  • 调度：可抢占式，高优先级先运行。
  • 互斥：信号量 Semaphore、互斥锁 Mutex。
  • 通信：消息队列 Queue、事件。
  • 中断：ISR 快速响应硬件事件。
